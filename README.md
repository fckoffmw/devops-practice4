# Практическая работа №4

Практики DevOps в современных методологиях разработки.

Основной вариант задания: Jenkins Pipeline имитирует сборку и развёртывание проекта из GitHub. Развёртывание реализовано копированием артефакта в учебные каталоги `deployments/staging` и `deployments/prod` внутри рабочей области Jenkins. Это не развёртывание публичного сервиса.

## Состав

- `Jenkinsfile` — декларативный конвейер CI/CD.
- `src/index.html` — исходный учебный артефакт.
- `scripts/build.sh` — подготовка артефакта.
- `scripts/test.sh` — проверка содержимого.
- `deploy` — учебное развёртывание.
- `smoke-tests` — проверка файлов окружения.

## Настройка Jenkins

1. Установить плагины Pipeline, Git, Credentials Binding, Mailer и Pipeline Stage View.
2. Создать учебные учётные данные типа Secret text с ID `practice4-demo-key` и произвольным демонстрационным значением. Не использовать реальные ключи облачных сервисов.
3. Настроить SMTP для учебного почтового сервера Mailpit: хост `mailpit`, порт `1025`, без TLS и аутентификации. Сообщения остаются в локальном стенде.
4. Создать задание типа Pipeline. Выбрать Pipeline script from SCM → Git, указать URL этого репозитория, ветку `*/main` и Script Path `Jenkinsfile`.
5. Запустить сборку. На этапе Approval подтвердить учебный деплой.

## Проверка обработки ошибок

Запустить сборку с параметром `SIMULATE_FAILURE=true`. Этап Test завершится ошибкой, дальнейшие этапы будут пропущены, Jenkins отправит сообщение в Mailpit. Затем запустить обычную сборку и подтвердить деплой: её статус должен быть SUCCESS.

Перед очисткой рабочей области Jenkins сохраняет артефакты сборки и файлы окружений. Их можно скачать со страницы соответствующей сборки.

## Локальная проверка скриптов

```sh
sh scripts/build.sh
sh scripts/test.sh
sh deploy staging
sh smoke-tests staging
sh deploy prod
sh smoke-tests prod
```

Скрипты используют POSIX shell. Docker для этих скриптов не требуется; в практической работе Docker используется для запуска Jenkins и локального SMTP-сервера.
